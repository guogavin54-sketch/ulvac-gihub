# 页面开发与设计还原规范

适用于本项目的页面新增、改版与设计稿还原。

## 1. 复用公共组件和布局

- 复用项目现有的 Header、Footer、共享样式和交互脚本，以首页为统一基准，不另造页面专用版本。若公共结构尚未独立封装，沿用首页现有结构和共享逻辑。
- 沿用现有页面的内容容器、最大宽度、左右留白、对齐规则和响应式断点。优先复用现有布局类和 CSS 变量，不另设一套全局布局规则。

## 2. 按设计稿做像素级还原

- 开发前提取并通读目标页面的全部设计导出代码和样式片段，核对各区块、组件状态、字体、图标和图片资源。按项目架构实现，不直接照搬导出代码，也不得用整页截图代替页面实现。
- 在同一视口下逐区对照设计稿，核对颜色、字体、字号、字重、行高、间距、尺寸、圆角和图片裁切。优先使用项目中与设计稿匹配的组件、样式变量和素材。

## 3. 复用现有交互和滚动渐入

- 沿用现有页面的交互逻辑和共享动画初始化方式。目标页面各内容模块均接入滚动渐入，保持触发时机、位移、延时、过渡时长和缓动曲线与基准页面一致，不重复实现一套动画监听。
- 确保渐入动画不与悬停、键盘焦点等交互互相覆盖；系统启用「减少动态效果」时，按项目现有方式处理，确保内容始终可见。

## 4. 保持响应式和代码一致性

- 检查桌面、平板、手机及断点两侧的容器宽度、网格重排和文字换行，确保无非预期横向溢出、内容遮挡或布局错乱。
- 页面专属样式限定在当前页面作用域，避免影响公共组件或其他页面。交互逻辑遵循现有代码规范；变量、函数、类名和图片文件名使用清晰的英文语义命名。

## 5. 开发完成后验证

- 在 Chrome、Edge、Firefox 和 Safari 中按可用环境实测，覆盖桌面与移动视口。将实际渲染与同尺寸设计稿对照，并与首页或参考页面对照公共组件、布局和动画表现。
- 逐区滚动验证渐入触发与完成状态，检查导航、悬停、键盘焦点和触屏交互。修正范围内的差异，明确记录已通过的浏览器、视口和检查项，以及未验证项；不得将未实测项标记为通过。
